# Project Constitution

Principles for the partition-problem program (see `task.md`). Keep it short; change it only by team agreement.

1. **Language.** All code is C++20 (`-std=c++20`), standard library only unless a dependency is trivial to ship on Windows. The one dependency is Boost.Multiprecision (header-only, copied into `third_party/`), for numbers of any size.
2. **Portability.** It must build and run on the Windows lab machines and on Linux. The demo machines have no compiler, so we ship a prebuilt, statically linked executable.
3. **Input format.** A text file. Line 1 is the number of sets `N`. Each of the next `N` lines is one set: non-negative integers separated by single spaces; the reader also accepts extra spaces and tabs between the numbers and at the ends of a line. Values may repeat (multiset) and may be large (about 25 digits in the examples). Numbers may have any number of digits. The algorithms are templates over the type of the numbers, chosen with `--arithmetic`: Boost `cpp_int` (the default), our own `BigUint` with a configurable base, or **unsigned 128-bit integers** (`unsigned __int128`, a GCC/Clang extension), which have the limits of `task.md` section 7. The input constraints in `task.md` section 7 apply; a value or a running sum that violates them is an error with a clear message and a non-zero exit code, nothing is ever silently truncated. Examples are in `raw_regulations/AaC_example_*.txt`. Malformed input gives a clear error message and a non-zero exit code.
4. **Output.** Output is readable and colored (ANSI) by default, on both Linux and Windows: results, errors and warnings use distinct colors. On Windows the program turns on ANSI processing in the console at startup (`ENABLE_VIRTUAL_TERMINAL_PROCESSING`) and prints plain text if that is not possible. A plain mode with no colors is mandatory, enabled by `--no-color` and also automatically when stdout is not a terminal or `NO_COLOR` is set. The text content must be identical in both modes.
5. **Build.** A `Makefile` is the way to compile (`make`, `make windows` for the static Windows executable, `make test`, `make clean`); no CMake. The README also lists the same manual compiler commands, so the program can be built without `make`.
6. **Algorithms.** Every exact algorithm with exponential complexity comes with a polynomial-time approximation. Code, pseudocode and complexity analysis in the documents must match.
7. **Correctness first.** Every algorithm is checked against a brute-force solution on small inputs. Tests and sample inputs live in the repository.
8. **Simplicity.** Prefer clear code to clever code. Small functions, meaningful names, comments only where the reason is not obvious.
